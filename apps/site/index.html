01. How it works

Four steps, no smart contracts

Zcash has no contracts and Byte invents none. The guarantees come from two mechanisms: shielded Ironwood transactions, which hide value and participants, and viewing keys plus encrypted memos, which let a payee prove to itself that a specific invoice was paid. 

// 1. the agent asks for something that costs money
GET /report                              → 402 + invoice

// 2. the invoice names a FRESH address, used once, never again
payTo: utest1nmxcdnkh7e2lq4dqzaj22r4j0zzy37lr3y4vtjw…
memo:  BYTE1|<invoiceId>|<binding>

// 3. the client checks its spend guard, then pays — shielded
//    an observer sees a transaction happened. nothing else.

// 4. retry with the proof; the payee verifies with a VIEW-ONLY key
GET /report + PAYMENT-SIGNATURE          → 200 + the report

A fresh address per invoice

Two payments to the same merchant are not linkable through the address they arrived at. Byte mints a new diversified address every time.

Verification without spending

A facilitator holds a viewing key, never a spending key. Compromise it completely and it still cannot move a zatoshi — enforced by the type, not by a promise.

02. Try it

Watch a memo bind a payment

Every Byte payment carries a memo committing to the invoice, the amount and the destination, under a key only the payee holds. This runs the real computation — HMAC-SHA256, in your browser, nothing sent anywhere. Change the amount and watch the binding break.

04. Limits

What is not hidden

A privacy system described only by its guarantees will surprise someone, and the surprise is always worse than the limitation.

  • That a shielded transaction happened, and when. Timing correlation is not defeated.
  • Any transparent funding rail. NEAR Intents supports ZEC at transparent addresses only, so every deposit there is public. Byte's largest and least reducible leak.
  • Anything crossing pools. ZIP 318 reveals the net amount, which is why Byte refuses to cross rather than manage it.
  • Whatever an agent publishes about itself in its Agent Card.
  • Network metadata. The light server sees your IP and your queries.

Honest status

Hackathon-stage, built for the ZECATHON. Not audited. Ironwood-era wallet tooling is young — librustzcash has never run its shielded-pool test suite with Ironwood as the active pool, and Byte spends from Ironwood. Do not put mainnet funds behind it.
