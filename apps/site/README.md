# The Byte Protocol site

A single static page. No build step, no framework, no dependencies, and — deliberately — no
outbound requests at all.

## Why nothing is fetched

`connect-src 'none'` is set in the root `vercel.json`, so the page cannot make a network
request even if something later tried to. A site explaining a privacy protocol has no
business loading analytics, fonts or scripts from third parties who would then see every
person who reads it.

The memo demo is not a mock. It runs HMAC-SHA256 through the Web Crypto API, in the reader's
browser, over the same null-separated preimage as `packages/core/src/memo.ts` and
`crates/byte-walletd/src/memo.rs`. Verified against the real implementation:

```
protocol : cf8918f31c231522fdaebe6b28b6a36f
page     : cf8918f31c231522fdaebe6b28b6a36f
```

## On "connect wallet"

There is no wallet-connect standard for Zcash. ZCG approved a grant to build one on
**31 August 2026**, with milestones running into **late 2027**; the application says it will
"complete WalletConnect integration capabilities for the Zcash ecosystem", meaning they do not
exist yet. WalletConnect namespaces must be CAIP-2, and Zcash has no registered CAIP-2
namespace.

So the page does not have a connect button, because one would do nothing. It shows a real
**ZIP-321** URI instead — the payment-URI standard every shielded Zcash wallet implements, and
which Byte already emits for every invoice. Opening it hands the address, amount and memo to
whatever wallet the reader has installed.

The URI on the page was generated by `buildZip321` from `packages/core` and round-trips
through `parseZip321`.

Wallets listed as supported: Zodl (the February 2026 rebrand of Zashi), YWallet, Zingo,
Zecwallet, and Ledger (shielded signing added August 2026). Nighthawk and Zelcore are listed
as **partial** — they handle shielded ZEC in specific setups but unified-address support is
incomplete.

## What this page does not claim

Byte settles in shielded Zcash and nowhere else. The page does not say "payments across any
chain" — the NEAR Intents rail brings value *in* from another chain and its Zcash leg is
public — and it does not say "wrap", because Byte wraps nothing and has no contracts.

## What this is not

It is **not** the Byte console. The console reports invoice amounts, transaction identifiers
and balances — exactly what Byte keeps off the chain — and is owner-only, local, and served by
`pnpm console`. It must never be deployed publicly.

## A note on opening it locally

`crypto.subtle` and `navigator.clipboard` are only exposed in a secure context, so opening
`index.html` straight off disk with `file://` leaves the demo inert. The page detects that and
says so rather than sitting on a dash looking broken. Use `pnpm site`, which serves it on
`http://127.0.0.1:4321`.

## Deploying

Configured entirely by the `vercel.json` at the **repository root**. Leave Root Directory
empty (the repo root) and there is nothing else to set.

```json
"installCommand": "",
"buildCommand": "rm -rf public && mkdir -p public && cp apps/site/index.html public/index.html",
"outputDirectory": "public"
```

### Why it copies into `public/` rather than pointing at `apps/site`

`outputDirectory` is a directory **name**, not a path. Setting it to `apps/site` produced:

```
Error: No Output Directory named "site" found after the Build completed.
```

Vercel took the last segment and looked for a top-level `site/`. So the build command copies
the page into `public/`, which is a real top-level directory and Vercel's own default.
`public/` is gitignored; it only exists during a build.

`installCommand` is empty and `buildCommand` is overridden because otherwise Vercel finds the
root `package.json`, runs its `build` script, and builds all twenty-eight workspace targets to
publish one HTML file.

### If it 404s

Check **Project Settings → Build and Deployment → Root Directory** is empty. The giveaway is
the response headers: if `curl -I` shows no `Content-Security-Policy`, Vercel never read a
`vercel.json`, which means it was looking in the wrong directory. A 404 alone could be
anything; a missing header is specific.
